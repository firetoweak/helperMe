# 入口与授权

## 入口

```text
python console_chat.py
```

只走新栈。CLI 的输入读取与 Agent 推进并行：空闲时输入普通任务，Agent 执行期间输入的新文本作为 `UserInterruptReceived` 立即写入 Journal，并在当前模型 Step 提交后优先决策，不等待并行工具组闭合。

CLI 每次启动生成新的 Stream identity，并把它交给 `AssistantStreams.create(identity)`；`/new` 也执行同样流程。`/resume <stream_id>` 只打开用户明确指定且已持久创建的 Stream，包括尚无 Event 的空 Stream，不猜测“最近一个”。Channel 负责选择 identity；Assistant 应用服务负责接收给定 identity，Runtime 负责实际创建、持久执行与机械恢复。

`Ctrl+C` 是进程级退出，不表示 Agent Interrupt，也不写 Runtime Event。`Ctrl+D` 同样退出。

CLI 只处理能够确认来源的输入错误和控制信号。内部契约违规或未预期异常必须穿透 Assistant 与 Channel，在进程入口直接暴露，不能打印后继续运行，也不能降级成业务失败。

若 Tool 异常逃逸，已经持久开始但没有 Outcome 的 Attempt 自然保持 `unknown`，但当前进程不会捕获异常后自动继续。下次由用户明确 `/resume` 该 Stream 时，Runtime 才按 Recovery Contract 机械恢复；无法 reconcile 时追加 `CommandRecoveryRequired`。这样同时保留副作用不确定性和原始程序错误。

| 输入 | 事实 |
|---|---|
| 普通句子 | `UserMessageReceived` |
| Agent 执行期间的新句子 | `UserInterruptReceived` |
| `/new` | Channel 生成 identity，Assistant 交给 Runtime 创建新 Stream |
| `/resume <stream_id>` | Channel 选择已有 Stream；Assistant 重建能力后由 Runtime 机械恢复 |
| `/stop` | `TerminationRequested` |
| `/mcp` `/skill` | CLI 控制面，不进 Journal 当用户任务 |
| 待授权时的 yes / no | `CommandAuthorized` / `CommandRejected` |
| 待授权时的其他句子 | 仍是 `UserMessage`，下一步模型判断 |

## 两条边界

**副作用安全**：产品装配的 Tool Spec / Binding 显式声明 `requires_authorization`，签发 Command 时冻结该要求。需要授权的 Command 没有 `CommandAuthorized` 就不能 dispatch；模型不能批准自己。Runtime 不根据工具名、参数或模型措辞推断风险。

**意图**：这句话是什么意思，由下一步 Step 判断。Runtime / Assistant 不得因为“正在等授权”就丢掉用户话。

yes / no 在等待授权时由 Channel 映射为授权事实，因为那是人在回答产品的批准问题，不是模型该投的票。

MCP/Skill 安装与恢复使用 `helperme.tools.control.ControlApprovalRequest`，属于 `/mcp`、`/skill` 管理控制面；它不会写成 Runtime Command 授权，也不能让普通工具结果进入授权等待态。

当前内置环境工具保持原有策略，默认不要求逐次确认；这只是产品装配当前声明，不是 Runtime 的内置白名单。以后调整某个工具的策略只改其 Spec / Binding，已签发 Command 的授权要求不会随配置变化。

## 安装

安装或启用 MCP / Skill 走 `/mcp` `/skill`。对话 `yes` 安装尚未做。旧 Turn `BLOCKED` 不恢复。

## 持久

控制台 Journal：`~/.helperme/runtime_streams/journal.sqlite`。测试用 `MemoryJournal`。
