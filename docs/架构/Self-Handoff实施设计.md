# Self-Handoff 实施设计

2026-09-09。已按本文替换旧接续实现。本文记录同 Session 后台 Self-Handoff 的完整设计约束；当前代码结构、配置及持久格式见[Compact](Compact.md)。SYS／工具呈现的独立优化见[上下文窗口与前缀稳定性](上下文窗口与前缀稳定性.md)。

## 同 Session 的后台 Self-Handoff

### 三层与所有权

```text
完整 Journal：执行事实，持续追加
    ↓
已接纳 Handoff：不可变、有来源的语义材料
    ↓
Current ContextWindow：由切换事实重建的当前阅读视图
```

业务 Session identity、Journal、工具激活、委派关系及待处理输入保持连续。Runtime 从完整 Journal 归约执行状态；Assistant 仅改变下一次模型请求的阅读范围。压缩移出模型视图的事件不退出 Runtime 归约，不重新签发历史 Command，也不重新消费旧触发。

ContextWindow 属于 Assistant 投影，不成为 Runtime Core 状态。用现有 `DomainFactCommitted` 等窄入口记录交接接纳和窗口切换，不增加 compact 专用 Runtime Event 类型或语义分支。

“某次生成了这份 handoff”是持久事实。摘要内容可能有误，但接纳后不能重新生成并覆盖原节点。可以重建窗口指向和消息组装，不能假定模型能重建字节相同或语义相同的摘要。

### 后台并行与 P／Q

```text
B 在位置 P 冻结当前窗口及模型请求前缀
    ├─ B 继续正常决策和执行，新事实写入同一 Journal
    └─ H 后台多轮回读与交接 → handoff（覆盖截至 P）

handoff 就绪 → B 到安全决策边界 Q → 持久发布窗口切换
```

P、Q 都表示截至该位置，包含该位置。后台生成期间新增事实为 `(P,Q]`，必须完整进入新视图。P 前还可保留一段完整的近期对话，与摘要有意重叠，帮助维持局部语境；它不同于不得遗漏的 `(P,Q]`。

H 复用 Worker／执行机制，但拥有独立执行记录、决策游标与预算，不是 B 的并发普通 Step。H 的读取过程不作为 B 的业务对话逐轮注入，不竞争 B 的正常触发，也不拥有 B 的业务命令执行权。最终由 Assistant 将已接纳交接材料关联回 B。

### 冻结前缀与多轮生成

```text
P 处请求： SYS + TOOLS + 当前窗口消息
H 首请求： 原 SYS + 原 TOOLS + 原窗口消息 + 交接要求
H 后续：   同一前缀 + 已生成消息 + 只读工具结果 + 必要的预算提醒
```

冻结并复用 P 处实际模型输入的 SYS、工具定义与消息，不根据随后变化的目录重新组装，不从 Raw Journal 展开成更长的全文，也不在 H 后续轮次对冻结前缀做年龄脱水。业务 B 的现有脱水规则本轮不改。

保留原生工具定义，不临时换成仅 `submit_handoff`，也不为交接新增前置 Schema。缓存复用取决于实际请求前缀和服务端缓存条件，不因 Session identity 相同就保证命中。

H 可以多轮调用交接所需的只读工具，追溯关键历史和证据。历史读取的授权范围截至 P；P 之后的业务事实由新窗口尾部承接，不偷渡进摘要覆盖范围。读取外部文件或服务并不等于读取 P 时刻快照，必须保留其实际来源和时间语义，不能将后来的观察写成 P 前已经发生的事实。

工具定义可见不等于允许执行。Assistant 执行边界只开放交接所需的只读能力，禁止工作区修改、业务委派、控制操作和用户消息投递。回读能力须在源会话已有的基础工具面中设计，不能为了此次交接临时修改冻结 `tools`。不把只读权限判断交给提示词。

成功条件是模型提交非空交接文本，且该次响应没有工具调用；接纳后 H 停止自动推进。不能仅凭 `WAITING` 判断成功，因为它也可能代表等待工具结果。工具调用后的阶段性文本不作为最终 handoff，交接文本不经普通用户回复路径发送。

### Prompt 与 Harness 双重预算

Prompt 要求：优先利用已冻结的上下文，只回读影响接手的关键缺口；不重复读取已有材料，不把压缩扩展成调查任务；未知内容明确标注，不以全面核验为交接前提。临近预算时直接收尾。

Harness 分别限制模型调用次数、后台任务总耗时和输入上下文预算，并预留交接输出空间。总耗时覆盖模型生成、工具执行与等待，必须能终止挂起请求，不能只在调用之间检查。恢复任务不能重置已消耗的次数或重新获得整份任务时间预算。

临近上限可以在历史末尾追加收尾提醒，不能修改 SYS。达到任一硬上限即停止本次任务，留下明确原因；不发布半成品、不切换窗口，也不自动重新启动同一次压缩。阈值作为配置，在真实长对话测试中调整；当前工程初值为最多 8 次模型调用、总耗时 300 秒。

已知预算耗尽按任务协议表达；内部契约违规和未知异常原样暴露，不包装成正常交接成功。

### 窗口切换

发布发生在 B 当前模型决策及本轮直接工具调用收口后、下一次决策开始前。不能切换正在调用模型的冻结视图，等待授权等未收口命令不得遗失。无需仅为压缩等待全部 SubAgent 返回或主动收回，它们仍属于同一 Session。

新视图为：

```text
稳定 SYS + 当前工具面
+ handoff
+ P 前选定的近期完整对话尾部
+ (P,Q] 期间新增的原样模型消息
+ 切换后新增事实
```

尾部不经模型重写，不拆散工具调用与结果；保持已有外置引用及可回读来源。保留原有待决策／等待用户意图，窗口切换本身不制造一次额外的用户回复。

handoff Artifact 必须先持久保存；“交接已接纳”与“窗口已切换”是不同事实。只有已提交的切换事实才能改变 active view，内存指针不是事实源。发布检查来源窗口仍是当前窗口，防止过期交接覆盖后来的切换。

恢复时：交接已接纳但尚未切换，继续完成同一次合法发布，不重新生成；已切换则按记录重建视图。失败则保留旧窗口，不自动重试。旧窗口仍有预算时 B 可继续；若容量不足则暂停模型决策，继续接收输入并明确报告压缩失败或未完成，不能静默截断历史。

### 来源与多次压缩

窗口的最小关系包含窗口身份、父窗口、handoff 事实引用、摘要覆盖截止位置和保留尾部范围。active window 从切换记录投影，不建设独立的可变事实库。当前字段和持久格式见 [Compact](Compact.md)。

handoff 关联来源窗口、覆盖位置和实际冻结请求的 Artifact，复用现有请求记录及身份，不另建无需求的 hash／epoch 框架。Event ID 与 Step ID 保持原身份，回读接口明确自己接收哪种位置，不混用编号。

多次压缩读取的是“上一份 handoff + 保留尾部 + 新事实”，不是声称模型重新读过全部原始历史。来源窗口及冻结材料用于说明实际阅读范围；来源链最终可以追溯到 Raw Journal 和原始 Artifact。

模型可以为关键结论附可见的来源引用，但不能猜测未展示的 Step ID。引用是回查入口，不是结论正确性的证明。

### 交接可信度与能力连续性

删除“上一任所有行动一律据称、接班后统一后验”的协议。保持原有证据强度：计划不能变成已执行，完成声明不能变成已验证，未知事项仍标为未知。遇到矛盾或关键疑点再回读；后续尾部事实可以更新或推翻摘要中的结论。正常任务完成核验继续存在。

工具激活、委派与执行状态由完整 Journal 及运行对象维护，不依赖模型摘要恢复。压缩后无需重新加载已有工具，也不重置运行状态。工具 Schema 本身仍占上下文预算；本轮接受历史压缩不能解决工具定义独占预算的边界，不另建卸载机制。

## 实施替代与验收

本轮实施已移除 compact 专属的“创建接替业务 Session、切换入口路由、单次 `submit_handoff`、重建工具激活、统一后验”旧路径，不保留双轨或隐式回退。普通 Session 创建、SubAgent 和通用 Worker 能力不因删除旧接续路径而删除。

验收覆盖：

- H 首请求原样继承冻结前缀；多轮回读只追加，不派发业务副作用，不读取 P 后业务历史。
- 各项预算可终止多轮循环与挂起调用；工具等待不被误判为最终交接。
- P／Q 期间输入不丢失、不重复消费；尾部保留完整调用与结果；未回收委派不阻塞窗口发布。
- 切换前后中断能恢复唯一 active view；已接纳 handoff 不重新生成，过期结果不覆盖新窗口。
- 同一业务 Session、工具激活和委派关系持续有效；多次窗口切换可沿来源链回读原文。
- 本轮不改业务脱水规则，不扩张 Runtime Core 的语义职责。

脚本模型与进程测试用于验证机械边界，不代表真实模型的交接质量或缓存命中率已经评测完成。
