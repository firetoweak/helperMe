# Self-Handoff 实施设计

2026-09-09。方案二为优先实施、验证方向；本文是待实施设计，不代表代码已经完成。背景与现有交接协议见 [Compact](Compact.md)，方案一的滚动 checkpoint 保留为备选。

## 目标与范围

当前压缩者从空白 Session 逐页读取冻结历史，阅读结果不断累积，真实实验中在读完前便超过自身输入预算。改为在确定位置 P 建立 Self-Handoff 分支，直接继承原会话的活跃上下文，一次模型决策提交 handoff。原会话继续服务用户，接续仍采用现有 handoff、原样 tail、来源引用和稳定入口切换。

Runtime 不变：不新增 Event 类型、State 字段、归约分支或通用分叉接口。改动集中在 Assistant 的材料冻结、上下文装配、能力限制与 Host 编排。

## 已确认的分支语义

```text
                         ┌─ S0 继续交互和执行 ── tail (P, Q] ─┐
S0 截至 P 的历史与上下文 ─┤                                  ├─ S1 接替
                         └─ H 交接分支 → handoff（截至 P）────┘
```

- P 位于模型决策之间；已签发工具及等待授权的命令须收口，不迁移在途执行。普通委派可以在原分支继续，发布 Q 时仍要求完成回收；控制面操作不能由交接分支接管。
- H 继承过去的经历与来源，下一步职责明确变为交接，不继续原业务、不接收原分支后续用户输入。
- H 第一版只开放 `submit_handoff`，不开放来源回读、业务工具、委派或用户回复工具。目标是一次模型决策生成完整交接。
- handoff 提交成功后，H 不再自动决策。S0 继续推进或等待，是否切换由 Host 在安全边界决定。

这里实现的是具有完整历史来源的 Self-Handoff 分支。H 不继承 S0 的待执行命令、待消费触发或运行租约，不提供任意业务任务的通用执行分叉。

## 事实身份与持久化

P 之前的 Event、Step、Command、Outcome 仍属于 S0，保留原身份，不重新编号成 H 的执行事实。旧 Journal 和关联 Artifact 完整保留；此前发生过接续时，来源链也保留。

H 的自身 Journal 只记录本分支新发生的交接执行：

```text
compact.task（引用 S0、P 和冻结材料）
    → StepCommitted（提交 handoff）
    → 提交命令的 Attempt / Outcome
    → 等待，不再决策
```

复用普通 `DomainFactCommitted` 和现有任务启动机制。旧历史通过 Assistant 的上下文投影进入模型输入，不进入 H 的 Runtime 归约，因此没有重复消费原触发、重复执行旧命令的问题。

冻结材料保存为 Artifact，任务事实绑定来源 Session、截止位置及材料引用。原始身份与消息投影位置之间的对应关系保存在来源材料中；投影未显示的 Step ID 不要求模型猜测。handoff 使用可见的来源位置、文件或产物引用，需要定位具体 Step 时由持久来源对应关系追溯。

## P 处冻结与模型输入

S0 在调度边界完成冻结后即可继续，不等待 H 调用模型。材料冻结与输入接纳沿用现有 Host 协调，明确哪些已接纳事实属于 P，之后的事实属于 tail。

冻结的是 P 处投影后的完整活跃对话，包含此前接续的上下文、用户消息、助手行动和工具结果。沿用已有工具输出外置与脱水结果，不从原始 Journal 展开回未经精简的长历史。冻结后不因 S0 继续执行而变化。

交接请求由以下内容组成：

1. 原会话的系统行为约束，加上明确的交接用途要求。
2. 冻结的活跃对话，保持角色、顺序、工具调用与结果配对及来源关系。
3. 本次交接任务及覆盖范围。
4. 唯一可调用工具 `submit_handoff`。

原会话的动态工具目录不作为 H 的可执行能力继承；相关历史仍可见。实现时将系统行为约束与动态能力目录的装配分清，不能为了得到原提示词而把所有业务工具再次暴露，也不能直接用当前空白压缩者的提示词替代原约束。

复用 `CompactContext.prefix` 与投影器已有的前缀入口，将继承历史置于本分支任务之前。前缀仅注入一次，模型请求中不再出现逐页读取历史的工具结果。禁止同时注入冻结历史和它的原始展开版本。

## Handoff 契约

交接内容包含：当前目标、已确认决策、明确约束、已经完成什么、失败过什么及原因、正在进行什么、未解决问题、关键来源引用。

提示词要求区分用户决定与模型建议、已执行与计划执行、完成声明与验证证据、已知失败原因与推测。只描述截至 P 的情况，后续 tail 可以修正或推翻旧结论。Self-Handoff 不是独立核验，不保证发现原助手已经存在的误解。

响应必须且只能调用一次 `submit_handoff`，参数为非空交接文本。纯文本回复、其他工具调用或多个提交均按无效模型响应处理，不启动补写循环。结构完整性和语义质量先由提示词与真实任务评测验证，不在 Runtime 中增加内容判断。

提交复用现有按交接分支身份幂等接纳的机制；相同内容重复提交不重复发布，冲突内容直接报错。提交命令继续使用 `decision_on_outcome=False`。

## 预算与失败

沿用 `compact_threshold_ratio` 软阈值提前启动。启动前检查实际构造出的完整交接请求，计入原行为约束、冻结对话、任务说明与提交工具定义，不能仅沿用 S0 的历史用量。

沿用 `model_context_limit × input_budget_ratio` 作为输入预算，其余窗口留给输出等模型开销。例如 70k 窗口、0.9 输入比例对应 63k 输入预算与 7k 余量。这是容量预留，不等于当前 Provider 已具备强制输出 token 上限；第一版不据此承诺 handoff 必定在余量内完成。真实评测须记录交接输出与失败情况，再决定是否需要增加独立输出限制。

实际交接请求装不下时，明确报预算错误，不启动注定超限的交接调用，不自动转用方案一、截断原文或接受半份 handoff。

生成失败、无效响应和未知异常显式暴露，不自动重试生成，不切换入口。失败保留原诊断；S0 在原预算和调度规则允许时继续，输入仍可接纳，不能宣称失败后可无限继续。

H 的工作过程不输出给用户。复用底部 compact 状态和成功切换次数；启动前预算失败也须明确显示，不能留下永久“整理中”的状态。

## Q、tail 与切换

H 提交后沿用现有 Q 检查：S0 无在途命令、普通委派已回收、控制面无待处理操作，才能准备 S1。不要求整个用户任务完成，也不因交接完成而替模型取消委派。

同时修正当前 tail 从 `bundle.raw` 拼装导致工具输出重新膨胀的问题：tail 应从 Q 处已投影的对话中按来源位置提取 `(P, Q]`，保留既有精简与 Artifact 回读入口，不再经模型改写。P 处工具已收口，避免切出孤立调用或结果；前序交接前缀不作为本段 tail 再次追加。

在保存和发布前，按 S1 实际使用的系统提示、初始工具面、handoff、tail 检查完整输入预算，避免用 S0 的动态工具集合代替新会话的预算口径。

复用现有持久发布顺序、输入投递登记与幂等补交。成功后 S0 不再自动推进，用户入口保持不变；S1 原本该继续则继续、该等待则等待。旧执行事实不在 S1 重放。

## 恢复边界

恢复继续依据持久任务、handoff、准备记录与当前绑定，不依赖内存分支指针。恢复 H 时使用同一 P 和同一冻结材料，不重新从已增长的 S0 抽取历史。

已持久接纳 handoff 后不再调用模型生成第二份；待完成的提交按原身份处理。已经标记失败的生成不自动恢复重试。未提交的模型决策和未知提交状态按现有 Worker / Journal 恢复契约核对，不为 Self-Handoff 新增通用重试或回退机制。

准备好 S1 但尚未发布，以及已经发布但进程随后退出的情况，继续由现有准备记录和路由提交确定唯一当前 Session。

## 改动位置

| 位置 | 计划改动 |
|---|---|
| `assistant/compact.py` | 冻结继承材料；TASK 加载历史前缀；替换读页提示词；仅暴露提交能力 |
| `assistant/decision.py`、`assembly.py` | 装配原行为约束与交接用途；限制响应为一次提交；绑定相应能力 |
| `assistant/compact_host.py` | 启动时绑定冻结材料并校验预算；复用提交与切换；修正 tail 与 S1 预算口径 |
| `assistant/compact_store.py`、`worker.py` | 仅在任务材料绑定和恢复确有需要时调整；不新增独立分叉管理框架 |
| `assistant/context/` | 复用投影、来源位置和预算；确需调整时仅提供材料装配所需的窄能力 |
| `channels/cli/`、`supervisor.py` | 复用已有状态通知，保证失败与成功切换显示准确 |
| `tests/assistant/` | 增加 Self-Handoff 行为验证，替换压缩者翻页测试假设 |

删除压缩者必须调用 `read_compact_source` 的旧路径，不保留两种生成方式长期并行。接替会话仍保留按来源回读的能力，该工具不能整体删除。旧任务材料若不符合新契约应明确报错，不增加兼容读取模式。

## 实施顺序与验收

先完成冻结材料、任务装配与单次提交，再接入现有 Host 流程，修正 tail，最后验证恢复和状态通知。生产目录不放测试；不修改 Runtime 来满足上层测试。

验收覆盖以下行为：

- H 首次请求已包含 P 处活跃对话、原约束和先前交接材料；没有读页调用，只有一次模型决策和一个提交工具。
- H 不能调用业务工具；原工具不重复执行，原委派不被 H 恢复或接管。
- H 生成期间 S0 仍可接纳并处理新消息；新要求进入 tail，handoff 不冒充覆盖 P 之后的事实。
- 大工具输出保持外置与可回读，交接材料与 tail 不重复，不因接续重新膨胀。
- 启动超预算、模型无效响应与生成失败均不切换、不自动重试；已提交 handoff 恢复后不重新生成。
- 保留现有发布前后重启、消息去重、等待与继续意图、稳定入口和 compact 次数测试。
- 真实模型实验核对约束、纠正、撤回决定、未完成事项与证据出处，记录交接输入、输出、耗时；多次接续时观察语义漂移，不将流程测试通过当作摘要质量保证。
