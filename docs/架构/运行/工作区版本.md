# 工作区版本

> 工作区文件状态有版本，任何一步的改动都能退回去。**记录自动，回退显式。**

只解决文件，已经发生的外部副作用不可撤销。执行环境边界见 [Sandbox 与配置](Sandbox与配置.md)；分支与并行版本仍未设计，见[工作区](../未开始/工作区.md)。

「文件变成什么样了」是确定性归约，在执行边界自动完成；「要不要退、退到哪」是语义判断，由模型显式发起。**版本标识是实现层坐标，模型看不到它**，回退引用的是模型自己的工具调用 id。

## 不变量

**不碰用户的版本历史。** 独立对象库指向同一份工作树，用户的引用、索引、暂存与工作树状态一个都不动。因此工作区本身也不必是版本仓库。

**产品数据不随文件回退。** 产品数据目录排除在轨道之外，即使它位于任务根内部——把 Journal 卷进一次回退是事实源损坏。

**回退不丢数据。** 回退前强制记录当前状态，未记录的手工改动与其他会话的写入因此也退得回来。恢复中途失败时，那个救援版本必须随失败一起交出去。

**回退独占一个批次。** 并行写入落在恢复之前还是之后无法确定。同批出现其他调用是已识别的模型失败，不静默拆批。约束由工具自己声明，不在决策层认名字。

**一个工作区一条轨道。** 多条会话的版本交错在同一条线上，如实记录、不协调；一条会话的回退会连带撤销另一条的改动，这与它们本就共享工作区是同一个问题，见 [SubAgent · 只读边界](SubAgent.md#只读边界)。

**没有记录就要说出来。** 记录失败不阻塞推进，但必须留下明确事实让模型看见这一步退不回去——静默跳过会让「可以反悔」无声失效。

## 记录

**快照点是 Step 边界**，不是每次写文件之后：Command 并行执行时逐个记录会让版本与 Command 的对应作废，而 `execute_command` 是否改文件无法静态判断。取一个 Step 的全部 Command 结束后记一次，两个问题一起消失。归因粒度因此是「这一步的全部改动」，与 `get_changes` 不做变更归因一致。

**内容无变化则不产生新版本**，沿用上一版。

**范围含新建文件**——Agent 建的文件必须能撤销，这与 `get_changes` 的 diff 不含未跟踪内容故意不同。

**排除规则用 `.gitignore`，它不要求工作区是版本仓库。** 那只是一个写模式的文本文件，放在任何目录里都生效；工作区确实是仓库时额外认 `.git/info/exclude`。所以不存在「非仓库工作区没有出口」这回事，也不要为此发明第二套忽略机制。代价是回退只覆盖被记录的范围，被忽略的文件保持现状——这一点要在工具描述里讲明，否则模型会以为整棵树都退了。

**剪枝在前，失败在后。** 忽略的目录在下降之前剪掉：它不进快照，读不读得动都与记录无关。要记录的内容读不动则是真的记不成，不能为了「更健壮」把遍历错误一并吞掉，那会让「没有记录就要说出来」失效。工作区没有任何忽略规则时一次记录可能很大，如实承认，不加护栏。

**全局与系统 Git 配置整体关闭。** filter、行尾转换、工作树编码任何一条都能让快照存成与磁盘不同的字节，回退就会把文件写坏。用户的全局 ignore 因此不参与——这是该决定的代价，不是可以单独开口子补回来的遗漏。使用者需要知道它，见根 [README](../../../README.md)。

## 事实与引用

版本是一条 Assistant 领域事实，形状照抄 MCP Toolset：普通事实记版本身份，恢复时从已提交事实投影，内存那份只是可丢弃缓存。见[工具与能力](../能力/工具与能力.md)。**不新增 Runtime Event 或 State**。Step 携带的决策元数据不是容器——它随 Step 提交，而记录发生在 Command 全部结束之后。

回退参数是一次工具调用的 id，解析规则：

- **语义是「恢复到这次调用之前」**，取该调用所在 Step 的**前一步**那条版本；第一步落到初始基线那条。方向错了每次都会多退或少退一步，症状隐蔽。
- **前一步没有成功记录时解析失败**，不顺移到更早的一步——那会静默多撤销一批改动。
- **撤销一次回退**时改用那次回退自己的执行前救援快照，它包含两步之间的手工改动，比前一步的版本更准。
- **可引用范围等于当前上下文窗口。** 脱水与体积外置保留调用 id，但 [Compact](../上下文/Compact.md) 换窗口后早期调用可能整段不在上下文里。这是正确的边界：模型对那些步只剩摘要，不该回退自己已经不理解的文件状态。跨窗口的版本考古属于[工作区](../未开始/工作区.md)专题。
- **成功的版本与回退事实不渲染进上下文，失败的要渲染。** 模型只引用调用，不需要看版本标识；但记录失败必须看见，否则它会在「反正能退」的假设上下注。

## 触发

**人的入口是说话，不是按钮。** 「退回我改登录页之前」对应哪一版是语义判断，交给模型。更重要的触发是模型中途自己反悔，那不需要任何界面。

**回退不需要授权。** 写工具要授权的理由之一是不可逆，而「回退不丢数据」证明了它可逆；装上授权闸只会堵死自我反悔。

Web 显示版本事实，不做撤销按钮。**时间线上的会话节点位置不占用**——编辑消息已经在那里，而它是 fork 不是回退。

## 分层落点

记录与恢复属于 `helperme/sandbox`；「什么时候记录」和「这次调用对应哪一版」属于 `helperme/assistant`；`helperme/tools` 只放回退入口，不认识版本标识的来历。依赖禁令见[架构总览](../总览.md)。

## 不做

- 分支、合并、并行工作树（属于尚未设计的[工作区](../未开始/工作区.md)专题）
- 带 fork / merge 的工作区版本端口
- 向模型暴露提交、日志、比较工具（比较已有 `get_changes`）
- 把版本标识交给模型，或为它投影一份版本清单
- 让回退跨过 Compact 边界去指模型看不见的版本
- 让 Runtime 认识版本，或为版本新增 Event / State
- 碰用户的版本历史、引用、索引与暂存
- 自动回退（「失败了就退回去」是语义判断）
- 给子 Session 回退能力
- 把版本与 Journal 位置做成可双向导航的时间轴
- 回收对象库。轨道只增不减，一次内容变化存一份完整副本，工作区删除后目录也留着。保留期按什么定、回收掉的版本要不要告诉模型，都要真实用量才能答，现在不猜
