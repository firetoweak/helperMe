# 工具与能力

三种来源，三个端口。不要收成统一 Plugin 框架。

## 环境工具

`helperme/tools/` 提供读文件、写文件、管理、diff、执行命令。`helperme/assistant/builtin_tools.py` 按当前 Environment 装配，经 `ToolsExecutor` 变成 Runtime Binding。开工即可见。

工具返回体中的 `ok / code / error / hint` 是领域协议，供模型和对应 Adapter 理解，不是 Runtime 状态机协议。Runtime 不解析这些字段；Adapter 若要报告调用层失败，必须显式产生失败 Outcome，而不是依赖 Core 猜测返回 JSON。

Tool Adapter 负责吸收其能够预期并确认的错误：领域拒绝可作为普通结构化结果，确定的调用失败可显式报告失败 Outcome。只有未处理异常逃逸、Runtime 又无法确认外部效果时，才使用已有 `unknown` 兜底；不为异常原因扩张 Command 状态枚举。

## MCP（Toolset）

模型开工只看见目录和 `load_toolset`。点名成功后，**下一个 Step** 才出现 `mcp__{server}__{tool}`。

```text
enabled MCP Server 目录
  → load_toolset("mcp:server_id")
  → Host 发现工具，runtime.bind_tool
  → 下一 Step 的 tools 才含那些 Schema
```

Runtime 不认识 MCP。加载语义按 Stream 留在 Host，不新增 Toolset 专用 Runtime 状态或 Event。`/new` 开新 Stream。

更准确地说，Assistant 不另造“Toolset 已加载”内核事件：成功的 `load_toolset` 本来就会留下普通 `CommandOutcomeReceived`，其中固定记录 `toolset_id + revision`。连续交互或进程恢复时，`ToolSurface` 从这些已提交结果投影激活集合，再让 Provider 重连同一 revision；内存中的 `_loaded` 只是可丢弃执行缓存，不是第二事实源。原 revision 不可用时恢复明确失败，不静默升级。

模型需要管理 MCP 时，先调用常驻的 `load_management_tools(domain="mcp")`；从下一 Step 起才可用 `list_mcp_servers` / `test_mcp_server` 获取 Registry 与真实连接事实，并可见 MCP 控制提案。工具不从 enabled 推断健康，也不返回 `next_action`。模型解释事实并决定是否调用 `propose_mcp_install` / `propose_mcp_recovery` / `propose_mcp_update`。安装只接受未登记 ID；recovery 按冻结 revision 重测并重连，不因 enabled 跳过；配置变化必须走显式 update，不会借安装暗中覆盖。控制提案不会签发 Runtime Command；Step 提交后才准备方案，用户确认后由 MCP Application 执行。CLI 仍可直接走 `/mcp`。

领域代码：`helperme/mcp`。为避免遮蔽第三方同名 SDK，不使用仓库顶层 `mcp/`。Assistant 边界翻译位于 `helperme/assistant/mcp.py` 的 `McpToolsetAdapter`。

## Skill

Skill 是指令包，不是执行能力。投影为两个普通工具：

```text
已启用目录写进 load_skill 描述
  → load_skill(id) 返回主指令
  → read_skill_resource 读包内文本
  → 做事仍用普通工具 / MCP / execute_command
```

没有已启用 Skill 时，这两个工具不出现。`/skill enable` 后下一 Step 可见。Runtime 不恢复 `exclusive_batch`。

模型需要管理 Skill 时，先调用 `load_management_tools(domain="skill")`；从下一 Step 起才可用 `list_installed_skills` / `inspect_installed_skill` / `test_installed_skill`，并可见 Skill 控制提案。模型依据这些事实自行选择 `propose_skill_install` / `propose_skill_enable` / `propose_skill_update` / `propose_skill_repair`。update 面向健康安装包并冻结 diff 候选；repair 面向丢失或损坏包，只允许恢复 Registry 登记的原 hash，来源漂移不会被暗中解释成更新。所有变更都需独立确认；CLI 仍可直接走 `/skill`。领域代码：`helperme/skills`。运行投影对象是 `SkillToolCatalog`，它只生成两个普通执行 ToolSpec，不拥有执行循环。

## 不做

- 开工把全部 MCP 工具塞进扁平 Binding
- 把 Skill 做成 Toolset 或新循环
- 为 MCP + Skill + 判定做统一 Plugin 基类
- 用 Session 能力快照当 Runtime 内核状态
