# 上下文投影

模型输入由 `helperme/assistant/context/projection.py` 投影；预算和 Prompt 分别位于同目录的 `budget.py`、`prompt.py`。Artifact Store 位于 `helperme/assistant/artifacts.py`。已提交 Step 的精确请求与原始响应保存为 Replay Manifest Artifact，Journal 只在 `StepCommitted` 上保存其稳定引用，不把模型协议内容变成 Runtime State。

## Decision Context

> Decision Context 是 Step 开始时对“模型所见世界”的冻结快照。

它同时冻结：

- `observed_journal_position` 以内、且属于 `visible_event_ids` 的 Event；
- 当前 Criteria；
- System Prompt 与 Toolset 目录说明；
- Tool / Skill schemas；
- Model Context 投影结果。

Host 拥有的 Prompt、目录和 schemas 在 `decide()` 首个异步等待前复制。Journal 即使在读取期间继续追加，也按 Step 的 `observed_journal_position` 截断。Toolset 已在进程内加载但其成功 Outcome 尚未进入冻结 Decision State 时，不对该 Step 可见。

Step 执行期间到达的新 Event、Criteria 或能力变化只影响后续 Step，不回写或刷新当前 Decision Context。每条 UserMessage 都按 Journal 顺序进入自己的后续 Decision Context，不抢占当前 Step。

模型返回后，Assistant 决策边界保存 `decision-replay-manifest/v1`，包括冻结依据、实际 messages、tools、model、Projector 版本、原始响应和 usage。Runtime Core 只接收 `RecordedDecision(decision, artifact_refs)`：它提交决策并携带引用，不理解 Manifest 内容，也不能依据 Manifest 自行改写模型决策。

```text
冻结可见 Event
  → 协议消息
  → 超大 tool Outcome 外置 Artifact
  → 保护窗：上一句 UserMessage 之后必留原文
  → 窗外、批次完整、已消费、成功 → Level 1 stub
  → InputBudget；超预算 fail fast
```

## 保护窗

上一句真实 `UserMessage` 之后的 Step / Outcome 不做年龄脱水。再从尾部补足 `recent_protection_tokens`（默认 10_000）。普通大小的失败结果、未消费结果和不完整批次不做年龄脱水；任何 Outcome 仍受强制体积外置限制。Interrupt 只存在于 Journal、State、Turn 与 Trace 的审计投影，不进入 Model Context；运行中输入的正文由关联的 UserMessage 正常投影。

## Artifact

按 Session 隔离，根目录 `~/.helperme/runtime_sessions`。单条 Outcome 超过阈值则外置，模型用 `read_artifact` 分页回读。模型始终看到顶层 `status / error_type / externalized`：执行状态不因外置丢失，`externalized` 只表达完整 Outcome 的存储位置。结果刚产生时保留少量 preview；移出保护窗且完整、成功、已消费后复用同一 Artifact 并清空 preview。`command_id → artifact_id` 是可丢弃投影缓存。

## 预算

`InputBudget` + tiktoken，读取 `model_context_limit` / `input_budget_ratio`。超预算抛错，不静默截断，不生成摘要冒充事实。

## 不做

- Level 2 摘要
- 把投影缓存当成第二事实源
- Runtime 内核做脱水
- 在模型调用前读取 Journal 尾部来“刷新”当前 Step
