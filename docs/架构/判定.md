# 判定

产品规则：

> **人负责目标；模型补全判定；人随时可以放松推断标准；只有人明确换事时才改目标。**

不恢复 Goal / Plain 并列，不恢复 Goal Loop，不引入 TodoList。

## 两层标准

| 层 | 权威 | 不完整时 |
|---|---|---|
| `user` | 当前任务的用户原话 | 允许不完整 |
| `inferred` | 分类 / 编译得到，如「必须跑测试」 | 系统补全；干活模型不能改 |

后一句用户话默认改 `inferred`（放松或推迟），不换任务。只有人明确改做别的事才换目标。`inferred` 被放松时版本化推迟，不删除。

Assistant Completion 领域对象叫 `CriteriaCommitted`、`JudgmentCommitted`，写入 Journal 时编码为 `DomainFactCommitted`。Runtime 不认识 Criteria、Judgment 或 Verdict。

## 分类

要不要严格收口，看确定性工具事实（写文件、跑命令），不看干活模型投票。

- 聊天：模型自己 `COMPLETE` 可直接收口，人就是 Judge。
- 写文件或跑命令：要过独立 Judge。

## 独立 Judge

另一套提示词、只读工具、不继承干活对话。Assistant Completion 的 `IsolatedJudge` 将结果写入 Journal。Evaluator 不得在隐藏路径调用 LLM。

Judge 位于完成声明与终态提交之间：`advance()` 只留下模型的 `COMPLETE`，Host 执行 Judge 后才调用 `finalize()`。因此即使该 Step 没有 Command，也不能抢在严格判定之前变成 `RuntimeCompleted`。

## continue 特权

仅严格收口任务：Judge 判 `continue` 时，没有新 `UserMessage` 也可以再开 Step。Completion Policy 将该 Judgment 编码为 `requests_decision=true` 的 Domain Fact；Runtime 只根据这个调度位开 Step。

不是任何任务都能在没新用户话时继续跑。

## 不做

- Runtime 内核里的 Goal 聚合、`TurnHost`、`max_goal_turns`
- TodoList / `rewrite_todos` / Sync Barrier
- 用 Level 2 摘要当完成证据
- 干活模型改分类结果

实现：`helperme/assistant/completion/criteria.py`、`helperme/assistant/completion/judgment.py`。
