# 自动化（未开始）

> 本文只记方向与已经排除的做法。方案确认前不按它实现。

系统除了接收人的消息，还需要接收定时触发、文件变化这类非 Channel 的外部事实。

## 共用的窄入口

这些来源和 SubAgent 结果回传共用一条外部事实入口，约束已经在用：事实必须说明来源，重复投递只能接纳一次，并明确它是否要求 Agent 继续决策。模型看到它时也必须能区分外部事实与人的发言。见 [Channel 接入契约](../入口/Channel接入契约.md)。

当前第一个实际使用者是 [SubAgent](../运行/SubAgent.md) 的结果回传。自动化要做的是在这条已经存在的入口上再接一类来源，**不是新建一条通路**。

## 「后台任务」不作为统一机制

这是本专题最重要的一条排除。定时触发属于外围调度，服务化属于接入方式，SubAgent 属于会话间协作，Kanban 属于会话内的任务判断——它们变化原因不同，只共享"外部事实进入会话"这一条路径。

把它们收成一个"后台任务框架"会把四种变化原因绑在一起，改任何一个都要动其余三个。

## 待设计

定时与文件监听不单独排期。将来实现时：

- 由触发本身产生稳定的去重身份，不靠时间窗或内容哈希伪造幂等；
- 计划时间和实际发生时间都交给模型判断，运行内核不解释"迟到了多久算失效"。

Automation 选择 Session identity 的方式与 Channel 相同：交给 Assistant 应用边界，不进 Runtime，见[项目架构方向](../../项目架构方向.md)。
