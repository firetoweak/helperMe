# Compact：后台压缩与会话接续

> 第一阶段已实现；机械交接通过脚本模型与真实 Worker 进程测试，真实模型的摘要质量和阈值仍待实测。相关运行行为见[上下文投影](上下文.md)、[Runtime](Runtime.md)与[Channel 接入契约](Channel接入契约.md)。

Compact 在后台生成 handoff 交接文档，旧 Session 继续服务用户；到安全的决策边界，以交接文档和未覆盖的原样对话尾部启动新 Session，并切换稳定对话入口。正常情况下用户无需等待或手动换会话。

## 范围与分层

本章只做上下文压缩与接续。摘要允许有损，是给模型阅读的材料，不是任务状态或新的执行事实。待办、准则的当场外化、作用域和退休，以及完成核验，留给第 3 章；跨目标长期知识留给第 5 章。不以这些机制为 compact 的前置条件，也不增加中间阶段。

实现以 **Runtime 不变** 为契约。Runtime 继续记录和推进给定 Session，不增加 compact 专属 Event、State 或执行分支。

| 所属层 | 职责 |
|---|---|
| Assistant | 压缩触发策略、压缩者任务与读取能力、handoff 和接续上下文投影 |
| Host / Scheduler | 独立 Session 生命周期、切换前收口、继续或等待的调度交接、切换恢复 |
| Channel / 入口路由 | 稳定 Conversation 与当前 Session 的绑定、输入归属和输出路由 |

Conversation identity 在切换前后保持稳定，Session identity 随接续变化。Channel 仍传入稳定对话 identity，Host 解析其当前 Session；输出反向映射回稳定 identity。

## 三个角色、两个位置

```text
旧 Session S0
 ├─ 截至 P 的固定历史 → 压缩者 C → handoff
 └─ P 之后继续交互和执行         → 原样 tail (P, Q]
                                      ↓
新 Session S1：handoff + tail + 来源引用
                                      ↓
稳定对话入口：S0 → S1
```

P 是摘要覆盖的最后位置；Q 是切换时旧 Session 接纳历史的最后位置。位置含义统一为“截至该位置，含该位置”，因此 tail 为 `(P, Q]`，覆盖无空隙、无重复。这是记录覆盖的保证，不是摘要语义无损的保证。

S0 的 Journal 和关联产物完整保留，可回读。C 是一次性的独立 Session，承担阅读、展开和归纳的上下文成本，完成后停止推进，不晋升为 S1；一次性不要求删除其审计记录。S1 只接收交接材料，不继承 C 的阅读过程。

C 复用现有 Session / Worker 机制；其产物用于新会话接续，不强行套用普通 SubAgent 向父报告并触发父决策的语义。

CLI 底部常驻显示当前实际 Session ID 和本对话累计成功切换次数；压缩期间显示“整理中”，handoff 就绪但尚未切换时显示“等待切换”，压缩者失败时显示“失败”。Host 在阶段变化时通知 Channel，次数从持久化的已发布接续记录统计，恢复对话后保留。这些显示不进入模型上下文或 Runtime 事实。

## 压缩者的读取契约

C 首先顺序阅读截至 P 的脱水对话，复用现有脱水与 Artifact 回读方向。视图保留角色、顺序和来源位置，工具记录保留调用与结果的必要信息，并明确省略内容及展开入口。内容过长可以分页阅读。

模型根据阅读需要展开原始消息和工具结果，不由读取工具判断哪些语义重要。不先单独抽出 userMessages，也不把历史等分后各自摘要。用户的简短确认、纠正和否决应放在相邻上下文中理解。

“用户要求最详细、模型行动次之、工具输出最精简”是交接文档的保真与详略原则，不是固定阅读顺序。关键工具错误可能决定任务尚未完成，不能因其角色而忽略。

C 的读取来源和截止位置由其自身持久任务记录绑定，只开放完成交接所需的只读窄口，不授予任意跨会话访问。S1 通过交接来源回读前序历史和产物。普通 SubAgent 的父上下文隔离规则保持不变。

## Handoff 交付契约

交付是一份有结构的自然语言文档，附旧 Session 来源和覆盖位置 P。来源及覆盖位置由上层绑定；文档中的语义判断由模型完成。

| 部分 | 内容 |
|---|---|
| 用户要什么 | 当前目标、要求的演变、明确约束、纠正和否决；关键措辞保留原话及出处 |
| 目前做到哪里 | 模型采取的行动、关键决定及理由；区分计划、已执行动作和声称完成 |
| 还有什么未解决 | 未回应的要求、未完成工作、阻塞与待确认问题；下一步建议标为模型建议 |
| 接手所需的证据与入口 | 关键工具结果、文件和产物位置、原始会话引用；长输出只保留影响后续判断的部分 |

按接手需要组织内容，不按 user / assistant / tool 写三份流水账；相关内容标明来源，不能把模型建议写成用户决定。模型的完成声明不能经摘要升级为已验证事实，工具证据也只证明其实际支持的结论。

Handoff 只描述截至 P 的情况。其后原样 tail 中的新要求和事实可以更新或推翻交接内容；接替模型必须结合二者继续判断。

Tail 是阅读材料，不把旧 Event 当作 S1 的执行事实重新提交或重放。已执行工具仍属于 S0，不因交接再次派发。“原样”表示对话内容不再经模型改写，原有脱水位置仍能回读完整来源。

S1 从最小能力面开始，所需工具和 Skill 按现有机制加载；handoff 可以说明用过哪些能力，不整体继承旧会话的激活集合。

## 允许切换的边界

切换发生在完整 Event 入账后、下一次模型决策开始前，由上层调度协调。当前模型调用不能被切到另一条 Session 中途继续；Step 提交也不代表工具执行完毕。

第一阶段不迁移在途执行。已签发工具须收口，普通委派须完成回收，才能确定 Q 并切换；等待授权的旧 Command 也不能因切换遗失。需要主动 reclaim 哪个委派仍由模型显式决定，compact 不在隐藏路径中替模型取消工作。

不必等待整个用户任务完成或进入等待用户状态。P 也应选择工具调用与结果完整的历史边界，避免摘要吞掉调用而 tail 留下孤立结果。

摘要准备期间 S0 正常推进。到切换点只确定 Q、准备引用与 tail、建立 S1 并切换入口，不再调用模型重写 tail。

## 生效与恢复

新会话的交接材料和必要接续信息持久准备好之后，才允许切换当前 Session 绑定。切换有唯一的持久生效点：此前接纳的用户消息属于 S0 并纳入其覆盖范围，此后属于 S1。输入投递与绑定切换必须协调，消息不能遗漏或因跨 Session 重投被重复接纳。

生效后 S0 不再自动推进，用户输出仍走同一个 Reply route。进程在准备或切换期间退出，恢复依据持久记录唯一确定当前 Session；不能只依赖内存指针，也不能让 S0、S1 同时自动继续同一对话。

调度交接保留原有意图：S0 原本将继续决策，S1 就结合 handoff 与 tail 继续；S0 原本等待用户，S1 也等待。已消费与待处理输入的接续依据由上层明确记录，不能把整段 tail 都作为新输入重新触发。Compact 完成本身不制造一轮用户可见回复。

## 触发与预算

第一版使用可配置的 token 软阈值，提前启动后台压缩。预算必须同时容纳交接文档、原样 tail、基础上下文和下一次模型输出；具体阈值及摘要目标体积通过实测确定。

触发策略与接续流程分开。模型上下文感知只作为后续可选触发来源，不是第一阶段的基础依赖，不为它向稳定提示前缀不断注入压力数字。

若压缩尚未完成，或尚未到达安全切换边界，而容量已不足以发出下一次模型请求，则暂停模型调用，继续接收用户消息。容量不足时不静默截断历史。未知异常、内部契约违规和持久化损坏原样暴露，不降级成普通失败或自动可继续状态。

“无感”指正常情况下前台持续交互、后台准备并自动切换，不保证永不等待，也不承诺摘要无损。

## 实现与持久化

`compact.py` 提供冻结阅读材料、只读来源工具、handoff 提交与 Worker 决策前检查；`compact_host.py` 编排后台压缩、接续与输入归属；`compact_store.py` 持久保存对话路由和压缩操作。`runner.py` 只在推进前调用上层边界，Runtime 代码没有变化。

压缩者以现有 `DomainFactCommitted` 承载的 `compact.task` 启动，模型只获得 `read_compact_source` 与 `submit_handoff`。读取工具按自身任务记录授权前序快照和沿接续链可回读的来源，不接受任意 Session；原文及产物缺失按损坏暴露。压缩者的工作过程和普通输出不进入用户对话，失败保留原始诊断并显式暴露，不自动重试失败的压缩操作。

来源快照保存脱水视图、原消息、允许回读的 Artifact 引用及前序来源。快照和 handoff / tail 上下文保存为 Artifact；S1 的首条 `compact.continued` 只绑定来源、P、Q、上下文 Artifact 和待处理来源事件。投影把上下文材料放在新会话消息之前，不将旧执行事实重放进新 Journal。首条接续事实是否要求决策取自 S0 的机械状态；多个待处理来源由接替模型结合整段上下文处理，不逐个重放旧触发。

Host 在 `runtime_sessions/conversations.sqlite` 中保存稳定入口绑定、每个源会话的压缩操作和输入投递登记。投递先登记目标，再写目标 Journal，成功后确认；同一对话锁覆盖接纳与切换。进程退出后，未确认的投递按原目标及原 delivery identity 幂等补交。它记录入口交付，不替代 Journal 的执行事实。

切换顺序为：冻结 Q 并检查新上下文预算 → 保存交接 Artifact → 持久记录准备好的 S1 初始事实 → 创建 S1 → 在路由库单个事务内发布当前绑定。准备记录落盘后，恢复先完成同一个切换，再接纳新输入。当前会话选择和输入归属不依赖跨 Journal 事务。

首次冻结 P 要求已签发工具收口；仍有普通委派时可以后台准备摘要，发布 Q 时才要求全部回收。压缩者中断后的未完成只读 Attempt 使用已有 Worker 恢复机制回退重读；提交 handoff 按压缩者 identity 幂等接纳，冲突内容报错。该恢复方式沿用现有只读子会话会丢失未完成 Attempt 历史的取舍。

配置 `runtime.compact_threshold_ratio`（初值 `0.55`）相对于输入预算，要求 `0 < threshold < 1`。它是 Assistant 的上下文策略，不是 Runtime 内核规则；当前配置必须显式提供，示例见根目录 `config.example.json`。初值是可调整的工程预算，尚无真实任务质量评测背书。handoff 由提示词要求简洁，不单独设置摘要长度比例；切换前校验包含系统提示、工具定义、handoff 与原样 tail 的完整模型输入预算。若仍无法容纳，则明确报预算错误，不发布过大的新上下文或偷偷再次概括 tail。

## 验收边界

- P 与 Q 的覆盖准确，工具调用与结果不因分界被拆散；来源及外置内容可回读。
- 压缩期间新消息和工具结果进入 tail；切换附近消息不丢、不重复接纳。
- 原有执行不会在新会话重放；继续决策与等待用户的意图保持一致。
- 切换前后中断恢复能唯一确定当前会话，旧会话不自动续跑。
- 多次接续后检验用户要求、纠正和未完成事项的保留质量，分别记录语义遗漏与机械交接错误。
- Runtime 生产代码、事件契约和归约规则保持不变。

## 待定方案一：按需启动的滚动语义 checkpoint

2026-09-09 讨论记录，保留为后续设计方向，尚未实现。

### 问题与已确定的约束

真实模型实验中，压缩者尚未读完冻结历史，自己的输入估算已达到 79,318 tokens，超过 63,000 的输入预算。当前分页只限制单次读取量，读过的页面及调用记录仍持续累积；通用脱水规则又将这段阅读过程纳入最近一轮的保护范围。

对于需要重新读取的长历史，不能假定整份材料能一次装入压缩请求；方案一采用分块处理或渐进式加载。同时，每次读入量和处理后留下的活跃上下文都要有界；仅缩小页面不能解决累计增长。方案二另行讨论直接继承原会话已有、受预算约束的活跃上下文，不将这一限制泛化为禁止复用当前上下文。

### 保留的思路

保留现有软阈值触发：接近水位时冻结截至 P 的历史，启动一次后台压缩；原会话继续运行，P 之后的新增内容仍由原样 tail 接续。滚动 checkpoint 只用于本次压缩任务内部处理冻结材料，不随每几个普通 Step 持续更新。

```text
达到压缩水位 → 冻结本次历史 → 按顺序分块

块 C1                 → 草稿 K1
草稿 K1 + 块 C2       → 草稿 K2
草稿 K2 + 块 C3       → 最终 handoff
```

这里 K 是语义交接草稿，不是 Runtime State、执行快照或长期记忆。每次由模型结合上一份草稿和下一块对话更新理解；需要时展开相关原文和证据。新草稿接纳后替换旧草稿，已处理原文和此前阅读调用记录退出下一次请求的活跃上下文，原始记录及来源仍保留供回读。只在同一个持续增长的会话里追加草稿，不能达到这一目的。

倾向按顺序滚动理解，而非各块独立总结后再拼接，因为用户的确认、纠正和否决可能依赖前一块的讨论。覆盖位置由程序管理，内容保留与语义更新由模型判断；不能在尚未形成承接材料时直接丢掉已读页面。

### 成本与取舍

滚动处理会反复输入上一份草稿，并输出完整的新草稿。假设原材料为 50k tokens，分成 10 块，每份草稿约 4k，则除原材料输入外，还会增加约 36k 的旧草稿输入和 40k 的草稿输出，尚未计入提示词、回读与推理消耗。这只是数量示例，不是预算配置。

本方案保留按需启动、仅在一次压缩内部滚动的方向。在给旧草稿、提示词、按需展开证据及输出留足空间的前提下，块尽量大，减少重复整理。暂不建设贯穿整个任务生命周期的持续 checkpoint；只有恢复、进度追踪等另有明确需求时，再评估其持续成本。

### 尚待讨论

块大小、草稿体积与回读预算如何分配，草稿必须保留哪些接手信息，以及多轮改写如何评测约束遗漏和语义漂移，均未定案。草稿的提交、持久化与中断恢复方式也留待具体设计。不因采用滚动处理而默认引入裁剪原文、接受不完整摘要或自动降级的规则。

## 方案二：Session 分叉的 Self-Handoff（优先验证）

2026-09-09 讨论记录，已确定优先实施验证，尚未实现。已确认的边界与落地安排见 [Self-Handoff 实施设计](Self-Handoff实施设计.md)；下文保留方案讨论背景，具体实施以该文档为准。方案一保留为备选。

### 核心思路

在准备生成 handoff 的 Step 边界，以确定的事实位置 P 分叉整个 Session。原分支继续服务用户；交接分支继承截至 P 的历史与可重建状态，下一步专门生成 handoff。这里的复制是 Session 分叉，不只是复制一份模型请求，也不要求原会话停下来等待交接。

```text
                      ┌─ 原分支继续交互和执行 ── 原样 tail (P, Q] ─┐
Session 截至 P ────────┤                                          ├─ 接替 Session
                      └─ 交接分支 → handoff（覆盖截至 P）───────────┘
```

Runtime 由事实归约状态，截至 P 的事实前缀为分支重建提供依据，无需复制正在运行的进程。交接分支直接使用原会话在 P 处的活跃上下文生成交接，不从空白压缩会话逐页重新读取历史，因此不会额外积累整段读页调用与结果。模型请求仍有输入和输出成本；Session 分叉不意味着复制模型内部隐藏状态，也不意味着免除模型对上下文的处理。

handoff 初步包含：当前目标、已确认决策、明确约束、已经完成什么、失败过什么及原因、正在进行什么、未解决问题、关键引用与 Step ID。区分用户决定与模型建议、实际执行与完成声明、已验证原因与推测；具体格式留待设计。

### 执行与接续边界

分支继承过去的事实，但不得再次派发过去已签发的动作。交接分支只负责生成 handoff，原分支承担后续业务执行；不能把复制 Session 实现成将历史命令重新执行一遍。倾向在工具已收口的位置确定 P，以简化分叉；具体分叉入口和交接 Step 的约束方式尚待设计。

保留现有 P/Q 接续方式：handoff 只描述截至 P 的情况，原分支后续新增内容进入原样 tail；到安全切换边界 Q，以 handoff、tail 和来源建立接替 Session，再切换稳定对话入口。交接分支不直接接管用户对话。

### 预算与取舍

必须在原会话活跃上下文仍能容纳交接指令并为 handoff 输出留足空间时触发。该方案复用的是当前受预算约束的活跃上下文，不是将无限增长的原始 Journal 全部重新装入；若当前上下文已经超限，分叉本身不能解决容量问题。

相较方案一，减少了重新读取历史和多轮改写草稿的成本，也利用了现有事实驱动结构。代价是交接可能延续原助手已有的遗漏或误解，不能将 Self-Handoff 视为独立核验。当前已确定优先验证这一方向，不代表已经实现或通过质量验证。

### 尚待讨论

后续讨论已确认保留旧事实身份、通过 Assistant 投影继承历史、自身 Journal 只记录交接执行，以及 Runtime 不变的边界。上下文装配、预算、失败恢复与验收安排已收录至 [实施设计](Self-Handoff实施设计.md)，不建设通用分叉框架。
