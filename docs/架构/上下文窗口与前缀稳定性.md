# 上下文窗口与前缀稳定性

SYS／工具呈现约束：固定规则、目录按消息追加、工具按名称排序。能力端口见[工具与能力](工具与能力.md)。窗口切换见 [Compact](Compact.md)，不要从本文进入交接设计。

## 范围

SYS 与工具描述不承载反复变化的运行状态，目录更新通过消息追加。

本轮不调整工具结果外置、年龄脱水及其保护窗。不引入通用工具调用代理，不改变原生 `tools` 接口。工具真实新增、删除、参数或能力约束变化时正常更新 Schema，接受必要的缓存失效。保持渐进式加载，不为缓存预先暴露所有扩展工具。

## SYS 与工具呈现

### 固定规则与动态事实

SYS 保存稳定的行为规则，不根据运行状态增删说明。SubAgent 使用固定条件规则：有尚未返回或收回的委派时，不把部分结论当作全部依据。删除按 pending 状态添加或移除 SYS 提醒的逻辑。

委派、返回与收回继续通过现有追加事实表达；程序维护执行、回收与投递幂等，模型依据事实判断还有谁未返回。不另建重复的状态通知机制。

工具定义只表达用途、参数、调用约束。目录不追加“已加载”标记，不拼入“最近失败”等运行状态。本分支调整的是定义和目录的呈现，不重新设计工具调用结果协议。

关键动态信息可以作为有明确来源和用途的上下文消息追加，例如：

```text
<tool_catalog_update>
新增：mcp:github，用于查询 GitHub 仓库和 PR。
停用：mcp:calendar。
</tool_catalog_update>
```

标签是内容标识，不提升消息权限。初始目录与后续变更必须形成可恢复、顺序明确的模型视图；不能每轮把最新目录插回历史开头，也不重复追加未变化的状态。具体消息角色按现有模型接口表达，并明确它是系统提供的事实而非用户发言。

### 工具顺序

最终暴露给模型的 `tools` 统一按工具名称排序。同一组工具的输出顺序不得取决于加载先后、并发完成或注册顺序。新增工具可以插入排序位置，已有工具之间的相对顺序保持不变。

排序只消除无意义波动，不承诺动态 Schema 变化后继续命中完整前缀缓存。

### Skill 目录

Skill 是指令包。`load_skill` 与资源读取工具的描述保持稳定，不把当前技能目录拼进工具描述。初始技能目录、后续目录更新和按需读取的正文通过消息提供；目录更新不回写之前的消息。

当前项目的 Skill 不自带执行工具。若未来 Skill 配套真实工具，这些工具仍按独立能力机制注册并加入原生 `tools`；不能把工具说明追加到消息误当作完成了执行注册。

## 验收

- 同一工具集合排序确定；加载状态不修改 SYS；Skill 目录更新不改写固定工具描述或旧消息。
- SubAgent 状态变化不增删 SYS；委派与回收事实仍准确追加。
