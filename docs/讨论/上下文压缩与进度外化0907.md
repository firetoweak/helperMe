# 上下文压缩：两阶段取舍（讨论稿 2026-09-07）

> 历史讨论稿。2026-09-07 已定案：compact 只做第一阶段，第二阶段的任务内进度与准则外化留给第 3 章，跨目标知识留给第 5 章。正式契约见 [Compact：后台压缩与会话接续](../架构/Compact.md)，第一阶段已实现。下文保留推演过程；其中“阶段二决定阶段一成败”、三层摘要与待办机械搬运等旧主张不再作为实施依据。读取方式采用先读脱水对话、按需展开，交付采用四部分 handoff。

## 问题

对话足够长之后，历史必然撑满模型的上下文。要在丢掉绝大部分历史的同时不丢掉关键信息。

取舍分两个阶段，必须分开谈：

- **阶段一：用什么形式换掉历史。** 已有结论。
- **阶段二：关键信息由谁承载。** 决定阶段一的成败条件，尚未定案。

阶段一可以独立成立；但如果阶段二不做，阶段一最脆弱的那部分就没有着落。

# 阶段一 · 换会话（形式取舍）

**决定：** 由一个一次性的压缩者读完旧会话、写出摘要；开一条新会话从摘要开始接替；旧会话完整保留、随时可回读。不做"会话内边聊边压"。

## 1.1 三角结构

来源、读者、接替者是三个不同的角色，不能合并：

| 角色 | 身份 | 命运 |
|---|---|---|
| 旧会话 | 唯一的原始记录 | 完整保留，可回读 |
| 压缩者 | 一次性的读者 | 用完即弃 |
| 新会话 | 接替者 | 继续对话 |

**"晋升"落在新会话，不是压缩者。** 压缩者必须读遍全部旧内容，读完之后它自己就是最膨胀的那份上下文——留下它等于挑了最该丢弃的那个。这一点很容易搞反，因为直觉上"谁写了摘要谁最懂"。

## 1.2 压缩者是一条独立会话，不是一次调用

压缩要做的事不是"把一段文本变短"：要分段读原文、把当初被省略掉的内容重新取回、内容超过一次调用容量时还要分批归并。这是一个带工具的循环。

把它放进独立会话的收益正是**上下文隔离**：膨胀发生在一条随后被丢弃的记录里，对话主线只拿到一条结论。

代价要说清：这要求压缩者能读另一条会话的完整记录，而这是我们此前明确禁止的（子会话不得访问父的上下文）。这道门要开，但只能开成窄口——**能读哪一条前序会话，由读者自己的记录指定**，不是任意指定，也不靠一份人工维护的白名单。

## 1.3 为什么不做会话内摘要

放弃"边聊边压、轻量丢掉中段细节"这个能力，理由：

- 粗颗粒够用，而且能把精力集中到"如何保留关键信息"这个真卡点上；
- 会话内摘要会衍生"摘要之上再摘要"，要处理多份摘要覆盖范围如何叠加，复杂度可观；
- 会话谱系（旧→新→更新）让每条记录头部恰好有一条不可变的摘要、来源指回前身，可追溯性更好；
- 不必先建一层将来还要拆掉的机制。

代价：每次瘦身都是一次完整换会话，粒度很粗。已接受。

## 1.4 摘要的职责是"未结清的账 + 指针"，不是复述历史

原文永远在旧会话里且可回读，所以摘要不必承担复述。

判据是**损失能否补救**：

- 漏掉一段技术细节 → 新会话回读原文就能补回来，代价是几次读取；
- 漏掉"用户否决过 A 方案" → 新会话会重新提议 A，且无从补救，因为它根本不知道有东西要查。

要集中保住的是后者。这也决定了摘要该写什么：让新会话知道**还欠什么**、**不许怎么做**、以及**去哪儿查**。

## 1.5 摘要要分三层写，因为三层的可靠性不同

| 层 | 内容 | 漏了能否补救 |
|---|---|---|
| 一 · 原样搬运（不经模型改写） | 未结清的待办、当前的完成条件、摘要截止之后那段原样的对话尾巴 | 不会漏，逐字搬 |
| 二 · 模型写，可回读 | 叙事背景 + 指针清单（关键文件、关键产物、旧会话位置、跑过的命令），每条带出处 | 能救 |
| 三 · 模型写，不可回读 | 约束、否决记录、放弃某条路的理由 | **不能救** |

第三层只存在于即将被丢弃的对话里，没有客观来源可查。所以它是唯一值得反复推敲的地方，而**目标应该是把它压到接近零**——这就是阶段二要解决的事。

三层混成一段自然语言写下来，新会话就分不清哪句能核验、哪句只能信。

## 1.6 硬规则：完成状态一律降级为"声称"

摘要只能写"旧会话中声称修好了 X，出处在此"，不能写"已修好 X"。

否则每换一次会话，就等于给所有未经核验的结论盖了一次章。这恰好是我们已知的一个病：对话变长后，模型会误以为修改已经完成。新会话要确认，必须自己去看工作区实际发生了什么。

## 1.7 覆盖范围必须严丝合缝

压缩者必须冻结在某个位置上读。于是必然出现一段空隙：**从摘要截止位置，到换会话真正生效之间新到达的对话**——人完全可能在压缩期间继续说话。

这段尾巴必须原样带进新会话，既不能被摘要吞掉，也不能留在旧会话里等于丢话。所以新会话的起点是"一条摘要 + 一段原样尾巴"，不是一条摘要。

## 1.8 换会话的前置条件

- **不搬能力，只搬账。** 新会话从最小能力面开始、需要什么再自己开启。这不是妥协：把旧会话的能力集合整体搬过去，是给模型铺它当前不需要的东西。摘要里提一句"之前用过哪些"就够。
- **还没交回结论的委派必须先收掉。** 它们的回传目标是旧会话，新会话收不到。
- **对话入口要跟着换。** 人面前的那条对话必须自动指向新会话，不能要求人手动切。
- **触发时机必须留足余量。** 至少还够做完"收掉委派 + 完成换会话"这几步。等撑满了才动，就会卡死：既腾不出空间做收尾，也换不了会话。

# 阶段二 · 关键信息由谁承载（内容取舍）

**核心问题：** 待办、准则、值得长期记住的东西，是靠**换会话时事后回忆**，还是在**被说出的当场就外化**成独立记录？

## 2.1 主张：当场外化

两种做法的可靠性差距很实：

- 事后回忆：一次性的、在信息已经堆成山的时候，去回想"还欠什么、不许怎么做"；
- 当场外化：增量的、在上下文还完整的时候，说出来就记下来。

后者把"记住关键信息"从**语义问题降级为机械搬运**——阶段一第一层那些原样搬运的内容，只有在这件事做了之后才真的存在。否则待办会掉到第二、第三层，由一次模型调用去回忆，而那正是整条链上最脆弱的一环。

这也是为什么阶段二决定阶段一的成败：不做它，阶段一里"不能救"的那一层就压不下去。

## 2.2 要立刻画的两条线

**作用域分层。** 待办和准则绑定当前目标，目标结束就随之退休；跨目标复用的知识才是长期记忆。这条线不画，"永远别强推代码"和"这次先别动构建配置"会进同一个池子，长期记忆就在没被设计之前先被实现了一半。

**别造第三个名词。** 我们已经有"完成条件"（做到什么算完）。准则是另一样东西（过程中不许怎么做）：前者服务于判断任务完成没有，后者服务于每一次行动决策。分开是对的，但要明说它们共享三条性质——目标作用域、换会话要一起搬、区分来源是用户明说的还是模型自己总结的。用户明说的模型不能自己推翻；模型自己总结的可以被后续事实改掉。

## 2.3 两条已经踩过坑的纪律

**提示里不放会变的数字。** "有未结清的待办"应该是一句固定文案，不带条数、不带内容摘要，让模型自己去查。带上一个每记一条就变的数字，会让整段稳定前缀的缓存反复失效——我们在并行委派的计数上已经吃过这个亏。

**聚合只在读的时候算，绝不写进记录。** 每条待办只记自己的状态变化，"还剩几条、进度如何"由读的一方现算。把聚合结果算好写进记录，一旦出现并行写入，两边就会各自读到对方写入前的状态、双双报出错误的剩余量——这个坑我们在并行委派上原样踩过一次。

## 2.4 未决：准则怎么退休（主要卡点）

准则的生命周期挂在"目标"上，可"用户是否换了目标"本身就是我们还没解决的判断问题，目前靠关键词猜。于是准则的作用域悬在一个未解决的问题上。

| 方案 | 好处 | 代价 |
|---|---|---|
| **A** 只增不减，只有用户显式撤销 | 确定，不让系统去猜目标换没换。猜错的方向是悄悄丢掉用户明确说过的话 | 准则池只增不减，长期成为常驻负担 |
| **B** 换会话时让模型复核一遍清单 | 给一次语义退休的机会 | 同时给了一次误删的机会 |

当前倾向 A。待查资料后再定。

# 两个阶段之外仍未定的

**触发阈值取多少、由谁触发。** 已有的实测只测了速度与缓存，没测任务完成质量。经验上，我们用的模型在约 47K 输入时理解力尚可、约 70K 之后明显退化，而硬性容量上限远高于此——所以换会话该由**质量软上限**触发，不是等撞到硬上限。具体数字需要用真实任务比。触发方是系统按余量算（机械判断），还是模型自己发起（语义判断），也未定；后者的已知代价是要在提示里放一个不断变化的压力数字，违反 2.3 第一条。

**第三层怎么验证。** 第一层可以验逐字相等，第二层可以验每个指针都能解析（解析不了算失败，不算警告），覆盖范围可以验拼回去没有空隙。第三层验不了。
