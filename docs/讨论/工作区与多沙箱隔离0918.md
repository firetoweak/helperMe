## 0. 一句话

把「用户指定的 Workspace」从**产品级单例**（被所有会话共享的全局根）改成**用户可命名、绑定到单个会话的沙箱边界**；会话只看得见自己工作区的那组根，隔离粒度从「全局开/关」变成「逐工作区」。**每条会话都必须属于一个工作区。**

## 2. 要改的既有设定

《多活跃会话》原文（「不负责」段附近）：

> 配置、Skill、MCP Registry 和用户指定的 Workspace 仍是产品级资源；Worker 在装配边界读取它们。多个顶层 Session 对同一 Workspace 的写入来自用户选择，不由 Agent 增加跨 Session 协调。

改动只落在「Workspace 是产品级资源」这半句：Workspace 变成**会话级绑定**的资源，随会话确定、不随全局配置变化。

**后半句仍然成立**：多个会话仍然可以共享同一个工作区，它们对同一工作区的写入依然「来自用户选择」，「不由 Agent 增加跨 Session 协调」。本次改造不引入任何跨会话协调。

| 事实 | 出处 |

| `AssistantConfig.workspace_root` / `full_access` 是从全局配置流进装配的单值 | `helperme/config.py` 的 `assistant_config_from_app` |
| 会话不记录任何 cwd/工作区归属；Journal 的 `events` 是通用的 `event_type + payload_json` 表 | `helperme/runtime/journal/sqlite.py`、`helperme/assistant/conversations.py` |
| 会话列表投影**已按 `updated_at` 降序**，并跳过 SubAgent 会话与无用户消息的空 Journal | `helperme/assistant/conversations.py` 的 `list_sessions()` |
| 四个入口脚本今天都**没有路径参数**（`web_chat.py` 只有 `--dev`），cwd 取决于从哪个目录敲命令 | `web_chat.py`、`acp_chat.py`、`console_chat.py`、`telegram_chat.py` |

**结论：改造不是推倒重来，而是「换谁来提供这组根」。** 沙箱层的多根、最深匹配、逐根权限都已经有了，缺的是「一组根跟一条会话绑定」。

## 4. 目标模型

### 4.1 工作区

一个工作区 = 一个沙箱边界，落地为「一组根 + 每根权限」。

- 主根（创建时填的路径）恒为 `task_workspace`，root_id 沿用 `"project"`，保持工具输出里的 `workspace_membership.root_id` 语义不变；
- 开启 `full_access` 时，把主机盘符以 `host_filesystem` 追加进该工作区的根集合（root_id 用 `discover_host_roots()` 现有的命名，避免与其冲突校验打架）；
- **id 与路径创建后不可变**；显示名可改（名字只是展示）；
- **不允许两个工作区指向同一路径**（`WorkspaceViewSnapshot` 本来就禁止同一物理路径重复注册，这条策略上延到 registry 层）；
- 数据结构上「一组根 + 逐根权限」天然支持挂只读的附加目录；**本次不做这层 UI**，也不需要在实现时改模型。

### 4.2 会话绑定

- 新建会话时确定工作区，**之后不可变**。要换工作区就新建会话。
- 归属落成**一条会话事件**（事件表是 `event_type + payload_json`，**不需要改 SQLite schema**）。绑定不可变 + 属于会话事实，正好适合走事件。
- 由此，前端的「工作区文件夹」与文档自洽：不是因为工作区**拥有**会话，而是因为每个会话**只属于一个**工作区。

**「不存在跨工作区」是由构造方式保证的**：会话的 `WorkspaceView` 只由它绑定的那一个工作区构造（外加该工作区开 `full_access` 时的 host 根），我们从不把两个工作区的根放进同一个 view。`WorkspaceViewSnapshot` 虽然结构上支持多根，但「跨工作区」在设计中无法表达。

### 4.3 权限下沉

`full_access` 从全局开关变成**工作区自身的属性**：新建工作区默认关闭；开启时才把主机盘符挂进这个工作区的根集合。其它工作区不受影响 —— 这是「多沙箱隔离」的实质，否则只是多了个分组。

### 4.4 registry

位置：`~/.helperme/workspaces.json`（与 `config.json` 同级）。草案：

```json
{
  "version": 1,
  "workspaces": [
    {
      "workspace_id": "workspace-3f1c9a2b4d5e6f708192a3b4c5d6e7f8",
      "name": "my-app",
      "task_root": "E:/projects/my-app",
      "full_access": false,
      "created_at": "2026-09-18T10:00:00+08:00"
    }
  ]
}
```

- **没有 `default` 特殊工作区**；id 一律 `workspace-<uuid4hex>`。
- 只存 `task_root` + `full_access`，**不存根列表**：宿主机的 host 根在装配时按 `full_access` 现推（`discover_host_roots()`），避免为「想象中的只读附加根」预建持久结构。
- 路径必须是**已存在目录**（`RootBinding` 本身就要求），创建时校验。
- 禁止**完全相同的路径**注册两次；**嵌套路径允许**（子目录可以是另一个工作区，`find_by_path` 的最深匹配正好支持它）。
- 注意：**不要**把 registry 放进 `runtime_sessions/` —— `SessionStore.journals()` 只认 64 位十六进制目录名，遇到非会话目录会直接抛 `ValueError`。

### 4.5 工作区怎么产生、会话落在哪、历史怎么归档

**不变量（后端强制）**：每条会话必须有 `workspace_id`。`POST /api/sessions` 缺 `workspace_id` 直接拒绝 —— 前端只是引导，真正的约束在后端。有了这个不变量，「归档」规则才是干净的。

**工作区的产生方式**：

| 通道 | 方式 |
|---|---|
| Web | **用户显式创建**（侧栏 ⊕，填名称 + 路径）。没有工作区时新建会话按钮不可用，界面引导先创建 |
| TUI / ACP | 从**启动路径 / `new_session(cwd)`** **隐式登记**：该路径未被任何工作区占用时，自动登记为一个工作区（名字默认取目录名）。`--workspace <path>` 显式优先（不存在则创建，已存在则复用） |
| Telegram | 没有目录上下文：`--workspace` 显式指定；没给时按下面的回退规则 |

- **隐式登记是「定案保留」的**：它本身就是在「新建会话之前」创建工作区，不违反上面的不变量。
- **与「自动发现」的区分（重要）**：隐式登记只看**你自己启动时站的那个目录**，一个路径，不猜任何别的目录，接近 `git init`；**扫描磁盘找项目**才是自动发现，明确不做。
- **路径不可变**：工作区一旦登记，路径不再变化 —— 否则路径会随启动目录漂移，违反 §4.1。

**新建会话的缺省落点**：

1. **最近一次聊天的工作区** = 最近一条**有归属**的会话所属的工作区。
   - 实现上**不需要新增状态**：`list_sessions()` 已经按 `updated_at` 降序，取第一条带 `workspace_id` 的即可。（若以后觉得从投影推导别扭，`~/.helperme/state/` 目录目前建了但没有消费者，正好可以放这类运行期状态。）
2. **还没有任何带归属的会话时**（刚建好工作区、还没聊过），落**最近创建的工作区**；如果连一个工作区都没有，那就是「必须先创建工作区」的空状态。
3. Web 顶部 New Chat 用以上规则；分组标题的 `+` 用**该分组**的工作区，不受此规则影响。
4. **Telegram 回退规则**（定案）：有带归属的历史会话 → 落「最近一次聊天的工作区」；完全没有 → 报错并提示加 `--workspace`。

**历史归档**：

- 那 **44 条**存量会话没有工作区归属，规则是「**没有 `workspace_id` 的会话不在前端显示**」（**隐式归档，定案**）。
- 数据保留在 `~/.helperme/runtime_sessions/`，一个字节都不删；将来若要做「归档列表」，只是把这条过滤放开。
- 因为不变量保证新会话必有归属，**不会再产生新的无归属会话**，所以这条规则不会随时间积累脏数据。

**取消的设定**（相比初稿）：`default` 工作区、「首次启动路径作为默认工作区根」、「旧 `config.json` 的 `workspace.root` 作为种子」。

## 5. 各通道行为

| 通道 | 工作区从哪来 | 新建会话落哪 |
|---|---|---|
| Web | 用户显式创建（侧栏 ⊕） | 分组 `+` → 该分组；顶部 New Chat → §4.5 的缺省落点规则 |
| ACP | `new_session(cwd)` 按**最深匹配**找已登记工作区；找不到则隐式登记 | 匹配到的工作区 |
| TUI | 同 ACP，`cwd` 取进程启动路径 | 同上 |
| Telegram | 仅 `--workspace` 指定 | 指定值；未指定则按 §4.5 的回退规则 |

按图与新决定补做：

- 分组标题**悬浮出现 `+`** = 在该工作区新建会话；
- 折叠行：`∨` 折叠箭头 + 文件夹图标 + 名字，整行点击切换；当前会话所属工作区高亮；
