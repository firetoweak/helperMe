# 工作区语义与工具路径契约

> 状态：设计完成，待实现
> 初次记录：2026-08-18
> 更新：2026-08-19
> 定位：Phase 6D Skill 实现前的基础设施回补

## 为什么先做

随着 MCP、Skill、Goal 和未来 SubAgent、Scheduler 的加入，HelperMe 已经同时涉及用户任务文件、Agent 持久状态、能力资源和进程工作目录。继续用一个模糊的 `Workspace` 表示这些空间，会让模型和代码都无法稳定判断路径属于哪里、应由谁访问、命令实际在哪里执行。

本专题不只是给工具结果补充 `scope`，而是先确立一条更基础的原则：

> Agent 不拥有工作目录；一次执行上下文选择一个 Environment，Environment 拥有路径语义。

Agent 负责目标与行动，Runtime 负责把行动放进明确的执行环境。这样本地、远端、容器或云端的差异可以停留在 Environment 以下，不进入 Agent Loop 和工具语义。

## 核心链路

```text
Session
│  Agent 对话、目标和持久状态
▼
TurnContext
├─ 本次 Turn 的有效配置与 Environment Selection
├─ EnvironmentSnapshot（在 Turn 内冻结）
└─ AgentStep 1..N
   └─ 一次模型调用及其直接产生的完整工具批次

EnvironmentSnapshot
├─ environment identity
├─ cwd
├─ workspace roots
├─ filesystem
├─ executor / shell
└─ permissions
```

每次模型调用、文件工具、命令工具和验证链都消费同一份环境快照。任何工具都不得自行读取进程 cwd、根据 root 名称猜测空间身份，或隐式切换到能力安装目录。

## 空间划分

### Task Workspace

当前任务的外部事实源，保存用户输入、项目文件、任务产物和 Git 变化。Environment 的 cwd 本身是一个 `root + relative directory` 位置，默认指向主要 Task root。

### Host Filesystem

用户额外授权访问的宿主机文件根。它可以被通用文件工具访问，但不因此成为当前项目、配置发现根或任务 cwd。

### Agent Home

HelperMe 的内部持久数据目录，保存 Session Artifact、MCP、Skill 和其他状态。它不是模型工作区，不注册为通用文件 root，只能通过相应领域工具访问。

### Capability Root

Skill、Plugin 等能力包的资源位置。能力资源可以由 Environment 提供，但其安装位置不属于 Task Workspace，也不能隐式成为命令 cwd。Skill 脚本的代码来源与任务执行位置必须分别表达。

## 模型可见契约

每个 Turn 都应向模型明确当前 Environment、cwd 和可访问 roots。模型不需要先猜测或调用工具才能知道自己在哪里。cwd 必须能定位到具体 root，不能成为脱离 workspace roots 的另一套路径基准。

文件工具继续使用逻辑 `root + relative path`，其中 path 始终相对显式 root 解析，不受当前 cwd 影响。空间身份由系统根据 root 推导，不要求模型重复提交 `scope`。所有路径型结果必须返回可定位信息：

```json
{
  "location": {
    "environment_id": "local",
    "scope": "task_workspace",
    "root": "project",
    "path": "src/main.py"
  }
}
```

命令工具的 cwd 同样由 `root + relative cwd` 定位；命令内部的相对路径再由 Shell 相对该启动目录解释。命令结果必须回显 `environment_id/root/cwd`，并明确 cwd 只是进程启动位置，不自动代表副作用被限制在该目录。失败结果在 root 已知时同样保留请求位置，避免错误脱离上下文。

## 继承与隔离

SubAgent 应创建独立的 Session 和运行状态，但显式继承或派生父级的 Environment Selection。共享执行环境不等于共享 Conversation、Goal、Todo 或其他可变状态。

```text
Runtime state 隔离
Execution Environment 可共享
Filesystem 变化作为外部事实协作
```

需要并行写隔离时，应派生独立 Worktree 或 Sandbox Environment，而不是在 Agent 状态层补并发规则。

## 不变式

- Prompt、文件工具、命令工具和验证链使用同一份 Environment 上下文。
- 带显式 root 的相对路径相对该 root 解析；只有工具契约明确省略 root 时才相对 Environment cwd，二者都不依赖 HelperMe 进程 cwd。
- 同一物理路径不应同时以 Task root 和 Host root 两种身份暴露。
- Agent Home 永远不是通用文件 root。
- Capability Root、Task Workspace 与权限 roots 是相关但独立的概念。
- 命令 cwd 是执行上下文，不是安全隔离声明。
- Workspace 切换必须替换完整 Environment 快照，不能只修改一个 cwd 字符串。

## 本次回补范围

1. 建立 Environment、cwd 与 workspace roots 的最小领域模型。
2. 由 Composition Root 显式构造 Task 与 Host roots，不通过名称猜测身份。
3. 在每个 Turn 中注入模型可见的 Environment Context。
4. 统一文件、命令和验证工具的路径定位结果。
5. 让 Goal Evidence 和后续 SubAgent 显式消费或继承 Environment Selection。
6. 保持 Agent Home 与 Skill/MCP 等 Capability Root 的领域隔离。

本次不建设完整远程执行平台、统一虚拟文件系统或复杂权限引擎。先把路径从哪里解析、动作在哪里执行、结果属于哪个环境这条链路固定，再在真实需求出现时增加新的 Environment 实现。
