# 异步工具执行链回补总结

## 目标

在接入 MCP 前，将外部执行主干统一为连续的异步调用链，同时保持既有工具批次、Evidence、Artifact 外置和 StopGuard 语义。

```text
AgentApplication
    ↓ await
SessionRuntime
    ↓ await
TurnRuntime
    ├─ await ModelCallService → LLMClient
    └─ await ToolsExecutor → ToolSpec.handler
```

纯内存领域计算继续同步；异步化不是工具并发化。

## 核心结论

- `AgentApplication.start/resume/execute`、`SessionRuntime.start/resume`、`TurnRuntime.run`、上下文摘要、模型调用和工具执行统一为 async。
- `ToolSpec.handler` 收敛为严格的异步契约，不在 `ToolsExecutor` 中保留同步/异步隐式双轨。
- 模型工具批次在本阶段仍按返回顺序逐个 `await`；后续并发回补已升级为同一 AgentStep 并发执行、按模型声明顺序提交。
- 同一 AgentStep 全部工具收束后，按声明顺序记录完整 Evidence、执行 Artifact 外置并写入 `ToolsState`；批次完成后才写 Conversation、Checkpoint 并检查中断和 StopGuard。
- 中断仍只设置 `TurnControl` 标记，不取消当前工具 Task；当前批次完成后才进入安全停止判断。
- handler、模型客户端和内部装配异常保持原始异常传播；只在既有外部输入边界返回预期错误。
- PowerShell Runner 使用原生异步子进程，超时后终止进程树并等待退出，避免 Turn 已结束但子进程继续修改文件。
- Goal 的 Contract、Executor、Judge 多 Turn 链路同步改为 async，没有建立同步 TurnHost 旁路。
- `AgentApplication` 通过通用异步资源上下文拥有 Application 级基础设施；Composition 可注入资源，但 Core 不引用 MCP。
- `asyncio.run()` 只存在于 Console 和独立 benchmark 的最外层入口，不进入 Runtime、Tool 或 Plugin 内部。

## MCP 后续接入点

MCP Plugin 可将 Application 级、懒连接的 Connection Manager 作为 `application_resources` 注入。Turn 继续只拥有 Toolset 选择状态和 ToolSpec 快照；物理连接由 Application 关闭时统一释放。

本次只完成通用异步前置，不引入 MCP 协议、配置或连接实现。

## 验证

- Core、Goal Plugin 自动化回归全部通过。
- 覆盖同步语义迁移、严格异步 handler、异常传播、工具批次安全点、Context Summary、Goal Loop、异步 CLI 子进程和 Application 资源逆序关闭。

## 审计后发现的边界（2026-08-12，已回补）

以下七项经代码与专项测试确认均为真实技术债，并已完成回补。最终实现与取舍见[《MCP 前置技术债清理总结》](MCP前置技术债清理总结.md)。下文保留发现问题时的历史分析。

回补后的边界如下：

- Toolset 在 `load_toolset` 时捕获一次规格，同一 Turn 后续 AgentStep 复用冻结快照；
- Task 取消先完成 Session、TurnRecord 与 active control 清理，再传播原始取消；
- AgentApplication 只允许在显式异步生命周期内使用，并拒绝活动 Turn 期间关闭资源；
- PowerShell 超时、取消和内部异常均收束进程树与输出 reader；
- 内部创建的 LLM Client 由 Application 关闭，外部注入实例保持调用方所有；
- `get_changes` 与 `grep` 使用原生 asyncio subprocess；
- 非 object 顶层 Tool Schema 在构造期直接失败。

专项测试覆盖了以上契约；短小本地文件 I/O 保持同步，不为了形式上的全异步引入线程调度。
