# 计划

本文记录 HelperMe 下一阶段要解决的架构问题。已经落地的结构与接口以[架构总览](架构/总览.md)为准，具体运行规则见[Runtime](架构/Runtime.md)。涉及边界调整时，以[项目架构方向](项目架构方向.md)校准。

当前架构已经闭合。后续功能复用现有的会话、事实记录、单步决策和命令执行机制；没有真实需求前，不提前增加领域状态机或统一框架。

## 判定遗留

- 将用户目标编译为可核验条件。目前仍使用“是否写过文件、是否运行过命令”这类固定模板。
- 无法确定用户是否更换目标时，主动请求用户确认。目前主要依赖关键词判断，其余输入默认延续当前任务。
- 独立 Judge 的真实模型调用与长任务的完成核验一起设计，不单独接通。

## 学习顺序

```text
1  工作区变更证据    已完成
2  对话上下文压缩    Self-Handoff 已落地，待真实模型质量评测
3  长任务            进度外化与完成核验
4  SubAgent          基础委派闭环已完成
5  Memory            带来源的长期记忆
```

## 第 1 章 · 工作区变更证据

已完成。模型可以取得从代码基线到当前工作区的完整变更，并明确知道哪些内容无法读取或被截断。这份证据只回答“工作区实际发生了什么”，不替模型判断任务是否完成。

> 仍然存在一个上层问题：对话稍长后，模型可能忘记主动核验变更，并误以为修改已经完成。这个问题属于长任务的完成核验，不继续扩张变更工具本身。

## 第 2 章 · 对话上下文压缩

### Session 级 LoopGuard

2026-09-10 首批已实现，见 [LoopGuard](架构/LoopGuard.md)。先用严格相同 action 连续重复策略，在决策末尾增量追加进展审视提醒；仅提醒模型，不判失败或强制停止。提醒及统一覆盖位置随 Step 原子提交，可随 Session 重放恢复。移除 compact 的 8 次调用上限与 300 秒总超时，保留上下文预算及其他局部超时。ActivityWatchdog 暂缓，留待 sandbox 执行生命周期专题。后续真实模型评测检验提醒质量，不扩展为第 3 章的完成判定。

### 当前实现与评测

已落实两条独立分支：前缀稳定性使 SYS 使用固定规则、目录更新追加到历史、工具按名称排序；同 Session 后台 Self-Handoff 切换 ContextWindow。当前实现读[Compact](架构/Compact.md)；设计约束对照[Self-Handoff 实施设计](架构/Self-Handoff实施设计.md)，呈现规则对照[前缀稳定性](架构/上下文窗口与前缀稳定性.md)。

Runtime Core 的调度语义不变，Step 新增不透明决策元数据以原子记录提醒；业务脱水规则不变。已删除接替 Session、路由切换、工具重载和统一后验的旧路径。脚本模型和 Worker 进程测试验证机械边界；下一步使用真实长对话评测摘要质量、多次窗口漂移、缓存命中率和预算阈值，不提前实施第 3 章。

## 第 3 章 · 长任务

长任务有两个不同的问题。

**进度外化**解决遗忘和漂移：把待办事项、当前进度和阻塞原因写成可重放的事实，模型不必只靠上下文记忆任务全貌。

**完成核验**解决过早宣布完成：模型声称完成时，系统先检查是否存在必要的客观证据，例如实际工作区变更和验证结果。证据是否满足用户目标仍是语义判断，应交给模型、独立 Judge 或用户，运行内核不替他们作结论。

现有简单任务继续自然运行：工具结果会触发下一步决策；模型没有下一步动作时，回到等待用户输入。定时唤醒不会让缺少新事实的任务变得更可靠，因此不作为长任务方案。

本章将 Kanban 与完成判定放在同一专题中设计，但保持两者职责分开。具体方案确认前，不接通声明式完成，也不增加独立 Judge。

## 第 4 章 · SubAgent

基础委派闭环已完成，当前设计见[SubAgent](架构/SubAgent.md)：主 Agent 可以把只读调查交给独立子会话；子会话自行工作，结论作为一条有来源的事实返回主会话。父可以用 `reclaim` 收回还在工作的子会话，与子自己交回结论走同一条回收通道。

第 2 章的 [Compact](架构/Compact.md) 复用独立 Session / Worker 机制完成后台压缩，其交接产物服务于原业务 Session 的新上下文窗口，不强行套用普通 SubAgent 向父回传并触发决策的语义。压缩专用读取授权不改变普通子会话的上下文隔离规则。

## 第 5 章 · Memory

Memory 保存值得跨任务复用的知识，原始会话记录仍保存完整经历。记忆由会话记录和产物提炼而来，必须能指回来源，不能成为无法核验的第二事实源。

```text
会话记录 / 产物
        ↓
提炼并保留来源
        ↓
存储与检索
        ↓
一次决策开始时冻结检索结果
```

检索结果在一次决策开始时确定，避免决策过程中上下文悄然变化。具体的提取时机、记忆结构、更新规则和检索策略留待本章设计。

## 后置专题

以下内容不属于当前学习主线。已有结论保留，剩余问题在真实需求出现或测量证明必要时再展开。

### Runtime 性能

运行记录是唯一事实源；上下文摘要不能兼任运行快照。未来若完整重放成为明确瓶颈，可以让快照记录自己覆盖到的位置，恢复时只重放之后的新事实。投影规则或事实结构变化时，旧快照必须明确失效。

是否调整数据库持久化策略或连接方式，应以测量结果为依据，不能用较弱的持久化保证换取未经证实的性能收益。

### 运行中到达的新消息

这一调度规则已经落地：新消息立即记入当前会话，但不会打断已经发出的工具调用。当前一轮结束后，新消息优先成为下一轮决策的起点，避免旧工具结果抢先触发一次基于过时上下文的判断。

取消当前工作、终止外部进程和通用中断协议尚未设计，它们是独立专题。

### 外部事实入口

系统除了接收人的消息，还需要接收子任务结果、定时触发或文件变化等外部事实。这些来源共用一条窄入口：事实必须说明来源，重复投递只能接纳一次，并明确它是否要求 Agent 继续决策。模型看到它时，也必须能区分外部事实与人的发言。

“后台任务”不作为统一机制。定时触发属于外围调度，服务化属于接入方式，SubAgent 属于会话间协作，Kanban 属于会话内的任务判断。它们变化原因不同，只共享外部事实进入会话的路径。

当前第一个实际使用者是 SubAgent 的结果回传。定时与文件监听不单独排期；将来实现时，由触发本身产生稳定的去重身份，并把计划时间和实际发生时间都交给模型判断。

### 多活跃会话

已落地，见[多活跃会话](架构/多活跃会话.md)：每个活跃 Session 使用独立进程、完整 Runtime 和独立 Journal；Host 只管理生命周期和投递。Host 重启后只恢复显式选择的 Session，恢复父会话时沿其委派事实恢复未回收的子会话，不扫描无关会话。

租约到期只开放竞争，只有更高 `generation` 真正接管后原 owner 才失去提交权。所有 Session 的未知 Attempt 都保留、不自动重试；SubAgent 恢复时发现未完成 Attempt，会沿现有 report 链路向父会话报告执行中断、结果未知，由父模型决定下一步。子 Session 的未知异常在 Worker 退出前先按现有 report 链路回收，再把原始失败交给 Host。多个顶层 Session 对同一 Workspace 的写入仍由用户选择，不增加跨 Session 协调。
