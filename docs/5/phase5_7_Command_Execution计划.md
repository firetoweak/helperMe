## Phase 5.7 Command Execution 计划

状态：完成（第一版实现、行为测试与真实 Agent Benchmark 均已通过，2026.08.07）。

### 目标

让 Agent 在可信的本机开发环境中使用 PowerShell 执行真实工程命令，并根据命令结果继续行动。

本阶段增加的是现有文件工具无法替代的执行能力，包括依赖安装、构建、测试、格式化、静态检查、Git 和包管理。验收目标不是“能够启动子进程”，而是 Agent 能组合文件工具与命令执行工具，形成执行、观察、修改、验证的任务闭环。

### 职责边界

文件工具负责有边界地发现、读取和修改 Workspace 内容；命令执行工具负责调用本机 CLI、运行项目代码和触发外部程序。

命令产生的文件修改属于 Workspace 外部事实，不自动注入 Context。Agent 必须通过文件工具、Git diff 或后续命令重新读取和验证真实结果。

命令执行工具不负责：

- 代替文件工具进行常规文件发现、读取和编辑。
- 把命令退出失败转换为 Runtime 内部异常。
- 为命令产生的副作用提供事务或自动回滚。
- 提供不可信代码的操作系统级安全隔离。
- 承担后台任务、调度或长期进程管理。

### 第一版能力

- 使用 PowerShell Shell 执行完整命令字符串。
- 支持参数、引号、管道、重定向和命令连接等 PowerShell 组合语义。
- 调用 Git、Python、Node.js、包管理器及其他本机已有 CLI。
- 执行依赖安装、构建、测试、格式化和静态检查。
- 返回退出码、标准输出、标准错误、超时和截断信息。
- 允许 Agent 根据失败结果继续调用工具并修正问题。

第一版只承诺 PowerShell 语义，不设计跨 Shell 的通用命令模型。

### Workspace 与访问边界

- 每次命令执行必须绑定一个已配置的逻辑 Workspace root。
- `cwd` 只能使用该 root 内的相对路径，拒绝绝对工作目录和越出 root 的相对工作目录。
- `cwd` 约束只决定命令从哪里启动，不限制命令能够访问哪里。
- 命令字符串可以包含绝对路径，也可以通过 CLI、子程序或网络访问 Workspace 外部资源。
- 不解析命令字符串中的路径，也不使用路径检查或命令正则过滤伪造安全沙箱。

因此，“命令绑定 Workspace”是运行上下文约束，不是进程权限边界。

### 信任与安全定位

第一版仅面向用户明确指定并信任的本机 Workspace。依赖安装、构建和测试可能执行项目代码以及第三方依赖脚本；本阶段不具备针对恶意代码的隔离能力。

涉及真正不可信代码时，必须另行引入容器、虚拟机或操作系统权限隔离，不在本阶段内伪造这一保证。

子进程环境必须由明确策略构造，禁止直接继承完整 `os.environ`。第一版允许的环境变量集合及配置入口在架构设计阶段确定。

Git 提交、推送、发布以及其他显著外部状态变更，只能在用户任务明确授权时执行；工具能力本身不扩大 Agent 获得的权限。

### 执行与结果契约

- 命令以非交互方式执行，不提供 stdin 交互和 PTY。
- 每次执行必须有有限超时，不能无限占用当前 Turn。
- 默认分别捕获 stdout 与 stderr；如果命令自身通过 Shell 重定向或合并输出，则以 PowerShell 语义为准。
- 非零退出码是一次真实的命令执行结果，不是 Runtime 内部异常。
- 命令未找到、无法创建进程和超时等预期执行失败，通过工具结果如实表达。
- 工具内部的编程错误保留原始异常，不伪装成命令失败。
- 输出必须在捕获阶段保持有界，不能先无限读入内存，再依赖 Runtime Artifact 或 Context Compression 补救。
- 截断结果必须明确标记，并提供能够支持 Agent 判断的头尾内容与原始规模信息。
- 超时后当前工具调用必须结束；进程树终止保证在架构设计阶段进一步确定。

### Benchmark

准备一个临时 Git 项目，其中包含依赖、构建入口和至少一个失败测试。只给 Agent 用户目标，不提供固定命令步骤。Agent 应自主完成：

```text
检查项目结构
    ↓
选择并执行依赖安装命令
    ↓
运行测试并读取失败信息
    ↓
定位、修改代码
    ↓
重新运行测试
    ↓
执行构建或项目检查
    ↓
查看 Git diff
    ↓
依据真实结果给出总结
```

通过标准：

- 依赖安装成功，或失败原因被如实识别并报告。
- 测试从失败变为通过。
- 构建或约定的项目检查通过。
- 所有显式 `cwd` 都位于指定 Workspace root 内。
- Agent 正确理解非零退出码、stderr、Shell 重定向和超时结果，不把失败伪装为成功。
- Agent 的最终回答与最后一次测试、构建及 Git diff 的事实一致。

网络安装属于人工集成验收，避免把外部网络波动作为单元测试稳定性的前提。

### Benchmark 结果（2026.08.07）

最终夹具使用已提交 lockfile 的本地依赖项目，预先删除 `node_modules`，确保 Agent 必须执行依赖安装，同时不让安装过程制造基线外 lockfile 噪音。只向 Agent 提供交付目标，不提供命令步骤。

Agent 实际完成：项目发现 → `npm install` → 构建 → 观察失败测试 → 定位并修改代码 → 重测 → 重建 → `get_changes` → 基于真实结果总结。评估器随后独立重跑测试与构建并检查完整 Git status；全部验收项通过。

测试过程中曾发现“调用了 get_changes”不等于“正确理解其结果”，因此最终评估同时校验 Workspace 实际状态与最终声明一致，而不是只检查工具调用序列。

可重复脚本位于 `tests/benchmarks/phase5_7_agent_benchmark.py`。脚本会在同目录生成 `phase5_7_last_report.json` 作为最近一次运行的本地报告；该报告不纳入版本管理。

### 独立行为验收

- 能执行带参数、引号、管道、重定向和命令连接符的 PowerShell 命令。
- 能在 Workspace root 及其子目录中执行命令。
- 拒绝绝对 `cwd` 和越出 root 的相对 `cwd`。
- 不限制命令字符串使用绝对路径或访问 Workspace 外资源。
- 能从受控子进程环境中找到 Git、Python、Node.js 和所需包管理器。
- 默认分别保留 stdout 与 stderr；命令主动重定向或合并时遵循 Shell 语义。
- 退出码准确，非零退出不会破坏后续 Agent Loop。
- 超时后工具调用能够返回，不再阻塞当前执行流程。
- 大输出有界，并明确返回截断状态和原始规模信息。
- stdin 不可交互，交互式命令不会无限等待。
- 命令失败后，Agent 仍能在下一个 AgentStep 读取结果并采取行动。

### 第一版明确不做

- 密码、确认提示、登录流程等交互式输入。
- PTY、终端 UI 或全屏程序。
- 长期运行的服务器和守护进程。
- 后台命令、任务 ID、稍后查询和实时日志流。
- 跨平台 Shell 兼容与完整命令语法分析。
- Turn 中断时的跨平台即时进程树取消保证。
- 自动重试失败命令。
- 自动提交、推送、发布或其他未经用户任务授权的外部状态变更。
- 不可信代码的强安全隔离。

### 第一版设计结论

- 固定调用当前 Windows 环境可发现的 `powershell.exe`，使用 `-NoLogo -NoProfile -NonInteractive -Command`，不经过 `shell=True`。
- 子进程环境从明确的 Windows 系统变量白名单构造，并固定注入 Python UTF-8 设置；其他变量默认不继承。
- 默认超时 60 秒，调用范围 1 到 300 秒。
- stdout、stderr 并发排空并分别有界捕获；每个流最多保留 6000 字符，其中头部 2400、尾部 3600，同时记录原始字符数和省略字符数。
- 第一版不保存完整输出到 Runtime Artifact，避免为日志外置提前扩展流式 Artifact 生命周期。
- 超时后在 Windows 上使用 `taskkill /T /F` 终止进程树，当前工具调用返回已捕获的有限输出。
- 命令通过 `workspace_effect` 显式声明预期副作用，默认值为 `may_write`；`COMMAND_COMPLETED` 与 `COMMAND_TIMEOUT` 仅在 `may_write` 时要求后续 `get_changes` 验证，明确的 `read_only` 查询不触发验证。
- Git 提交、推送和发布权限通过 Agent 权限规则及工具描述约束，不在命令执行器内解析 PowerShell 命令。
